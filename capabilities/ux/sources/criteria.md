# Design judgment areas

These areas organize questions relevant to a product interface. The user's purpose, requirements and adopted design remain the task context; this list does not create additional product features.

| Area | Questions it owns |
| --- | --- |
| Context | User purpose, audience, priority and applicable design authority |
| Navigation | Information organization, scope, selection and finding the next action |
| Visual | Hierarchy, typography, proportion, grouping, spacing and coherence |
| Interaction | State transitions, action continuity, input behavior and preservation of work |
| Feedback | Outcome understanding, scope, persistence and recovery information |
| Accessibility | Perception, operation, comprehension and assistive access |

Each area has its own entry in the [reference index](../../../references/index.json). Supporting details stay with that subject or the referenced original source. The model determines applicability and evaluates the actual result; a list of accessed sources is not that judgment.
